# 弹窗顺手 + 密钥小眼睛 (tavern-popup-polish) v1.7.0

**为手机上的 SillyTavern（浏览器访问）和 TauriTavern（安卓 WebView）做的**，桌面上也能用。
只动两处：**API 密钥框**和**输入类弹窗**，别的地方一个字不改。

## 它做了什么

### 1. 密钥框右边的小眼睛
- 「自定义 API 密钥」输入框右边（原生小钥匙左边）多一颗眼睛，点一下看明文，再点一下遮回去。
- 原生的密钥框是 `type="text"`，装上后默认遮成圆点，所以平时截屏 / 递手机都不会漏。
- 客户端存完密钥就会清空输入框，所以框空着的时候点眼睛 = 向后端要**已存的那把密钥**（走
  `/api/secrets/find`，跟原生「查看隐藏的 API 密钥」是同一个开关；如果客户端没开
  Allow Keys Exposure 会提示你去开）。
- 我们填进去的明文在你点「连接 / 加载模型」等任何按钮之前会自动抹掉 —— 否则客户端看到框里
  有字，会把同一把密钥再存一遍。你**自己手打**的内容不会被动。
- 顺带挡掉客户端把已存密钥写进输入框提示文字（placeholder）的行为，那里显示的是明文且不受遮罩。

### 2. 输入类弹窗（新增 / 改名 API 连接配置、各种「起个名字」）
- **更宽更高**：原生固定 500px、输入框只有一行文字高（很扁）。现在宽度可调（默认 640，窄屏自动
  贴到 `100dvw - 12px`），输入框最小高度 42px。
- **名字永远一行**：原生是 `rows=1` 的 textarea，名字长了会折到第二行看不见。现在 `wrap=off` +
  `white-space: pre`，超长就继续往右延伸，光标走到哪就滚到哪（滚动条隐藏，不占高度）。
- **输入法避让（v1.2.0 改了目标）**：输入法一弹出，把整个弹窗往上顶，直到**输入框和「取消 /
  确认」那一排一起露在输入法上方**（离输入法上沿留 10px）。上面那十来个勾选项该顶出屏幕就顶出去
  —— 这样不用收输入法就能直接点保存。唯一的红线是「正在输入的那个框不能被推出屏幕顶部」。
- **手指拉回来看上面**：顶上去以后，在弹窗任意空白处（标题、说明文字、勾选框区域、弹窗外的暗
  背景）上下滑动就能把它拉回来看，**滑动过程不会收输入法**（我们把这一串触摸的默认行为拦了，
  连带取消了 click 和焦点变化）。往下最多回到原位，往上最多到上面那个极限，都拉不过头。
  在输入框里滑动是选字、在按钮上滑动是按按钮，都不会误拖窗口。
- **拖动跟手（v1.2.0）**：位移写成内联 `translate3d`，不写 CSS 自定义属性 —— 自定义属性会继承，
  改一次弹窗里每个子元素都要重算样式，每帧几十次就是「拖起来卡卡的」的真凶。再加上一帧只写一次
  （touchmove 比刷新率密得多）、拖动时关掉过渡和背景模糊、拖动中不再做任何测量。
- **点空白处照旧**：轻点（位移 < 8px）不算拖动，原生该收输入法就收。
- **输入法一收就回原位（v1.2.0 修）**：不管是点空白、**输入法自带的收起键**还是返回键，
  也不管这一轮里你有没有用手拖过，弹窗都会滑回原位。（安卓上后两种方式不会让输入框失焦，
  v1.1.0 靠失焦判断，所以按收起键时会卡在被顶起的位置。）
- **不卡了**：原生开窗动画是 `scaleY(0) → scaleY(1)`（整窗竖向拉伸 → 每帧文字重排重光栅化）+
  背景实时高斯模糊 + 输入法弹出让 `100dvh` 变小导致弹窗当场变形，三件事同帧发生，就是那股顿挫感。
  现在换成 150ms 的位移 + 淡入（纯合成器动画）、开窗时不做模糊、并把弹窗高度钉在输入法弹出前的
  视口高度上。还嫌顿可以再打开「等动画结束再弹输入法」。

## 手机上的三种输入法行为（都测过）

安卓上「输入法弹出」在不同环境里表现完全不同，插件四路取信号，哪一路都能兜住：

| 环境 | 输入法弹出时发生什么 | 插件靠什么发现 |
| --- | --- | --- |
| 手机浏览器（Termux 里的 SillyTavern、Chrome/Edge 等） | 只缩 `visualViewport`，布局视口不变 | `visualViewport.height / offsetTop` |
| TauriTavern（安卓 WebView） | 原生层往页面注入输入法高度 | CSS 变量 `--tt-ime-bottom` |
| WebView 的 adjustResize 模式 | **整个布局视口**被压小，inset 恒为 0 | 记住输入法弹出前的最大视口高度当基线（只在手机 UA 下启用） |
| 都读不到（很少见） | — | 250ms 轮询兜底；实在测不到就只是不自动推，其它功能照常 |

另外两条只对手机有意义的处理：

- **窄屏（≤600px）收边距**：手机上「变宽」的空间几乎全在边距里 —— 原生弹窗左右各留 2em(≈30px)
  空白 + 自己 14px padding + 内容区 8px，380px 的屏幕输入框只剩 ≈320px。窄屏下这三层收到
  10 / 8 / 4px，输入框实打实宽出 30~40px（≈两个汉字）。
- **弹窗比屏幕高时可以拖着看**：手机上「新增API连接配置」有十来个勾选项，弹窗常常比屏幕还高、
  顶部被切掉一截（输入法 adjustResize 时尤其明显）。这时不用输入法也能上下拖，往下最多拖到
  顶部刚好露出来，松手不会被拽回去；一旦输入法弹出，立刻改回「以名字可见为准」。
- **安卓返回键 / 输入法自带的收起键都不会让输入框失焦**，所以「输入法这一轮」是靠视口状态翻转判断的：
  一轮结束 → 一定回原位并解锁；再弹出 = 新一轮，重新自动避让。不靠 `focusout`（那样会漏）。
- **兜底一路**：万一某个环境的输入法高度四路都读不出来，只要「焦点在输入框里」且「弹窗底边确实
  被压在可见区外」，也会照样往上顶。没在打字时绝不动任何弹窗。

## v1.7.0：插件面板默认收起 + 压住切换连接配置时的 Unauthorized 误报

1. **扩展面板默认折叠在插件列表里** —— 以前这个插件在「扩展」面板里默认是展开的，每次都要手动收一下；
   现在默认收起，点一下标题才展开（只影响本扩展这一块，不动别的扩展）。
2. **切换连接配置 / API / 预设时压住 Unauthorized 误报** —— 在 TauriTavern 上切 connection profile / 切 API /
   切预设后常会弹一条「后端错误 Failed to get chat completions status: Unauthorized (request id: …)」，
   但实际连接是好的。根因：切换时客户端会立刻打一发 `/api/backends/chat-completions/status`，
   这个请求不等 `waitUntilCondition`，可能用还没生效的 token，被上游回 401，再被后端包成那条 toast。
   本插件在「刚切完」+「连接还没真正建立」+「文案同时含 `chat completions status` 和 `Unauthorized`」
   三条全中时把这一条 toast 压住（默认开，可关）；真连不上 / 超时 / 文案不符的都正常弹，不会误伤真实报错。
   相关设置在扩展面板的新开关和「高级设置 → 切换连接配置后压住误报的窗口 (ms)」（默认 6000ms）。

## v1.6.0：记住「新增配置」弹窗里没勾的项

「新增API连接配置」弹窗上面那排勾选项是「这份配置要一起保存哪些设置」。以前每次打开都是全勾上，
每次都得重新点掉同样的几项。现在**点保存的时候会把「哪几项没勾」记下来，下次打开自动还原成没勾**。

- 只有点**保存**才记（点取消、点右上角关掉都不记）；输入框里按回车也算保存。
- 记的是**字段名**，跟界面语言无关；这次没出现的字段自动跳过。
- 全都勾回去再保存 = 记忆清空。
- 改名弹窗（编辑已有配置）的那排勾选项**不碰**。
- 不想要就关掉「记住上次没勾的项（新增配置弹窗）」。

实现上有个坑：客户端是**监听勾选框的 `input` 事件**来维护「这份配置不保存哪些字段」的，
所以光把 `checked` 改掉只是看着没勾、实际还会被保存 —— 还原时必须把事件补发出去。

## v1.5.0：点了就顶、不再回弹、名字变短、面板精简

1. **回位之后又闪一下跳上去** —— 修了。原因是收输入法之后焦点会被程序抢回输入框，
   插件把这次 focus 当成「输入法又来了」，就照着假定的高度再顶一次，下一拍发现没有又落回来。
   现在分得清了：只有**手指真的落在输入框上**、或者**弹窗刚打开客户端自己 autofocus**
   才算「输入法要来了」；程序抢回来的焦点不算。外加一层 450ms 的冷静期，回位过程中
   任何抖动的信号都顶不上去（用户真去点输入框会立刻解除，不影响响应）。
2. **弹窗推得太慢**（输入法都出来了弹窗还在下面）—— 现在「这个环境测不出输入法」这件事
   会**记在设置里**（`blindSeen`），所以只有第一次要等那 350ms，之后**手指一点输入框就立刻顶**，
   比输入法自己弹出来还快。弹窗打开时就顶好的话，连位移动画都看不见。
3. **新增 API 连接配置的默认名字**：客户端预填的是 `接口 模型 - 预设` 一长串，现在默认
   只留**模型名**。面板里可以选：只要模型名 / 模型 - 预设 / API + 模型 / 不改。
   重名会自动加 ` (2)`（客户端遇到重名是直接报错的）。
   只有确认是客户端**自动拼的**那串才替换 —— 改名弹窗、或者你自己打过的字，一律不碰。
4. **往上拖的范围可以设**了（默认「往上最多再拖 150px」）。以前能一路拖到只剩一个按钮，很难看。
   上限永远不会越过「输入框顶部出屏幕」这条红线，所以拖上去一定拖得回来。
5. **拖动更跟手**：图层在弹窗一出现时就提出来（以前是手指动了才提，第一帧要重新光栅化整个弹窗，
   那一下就是黏手感的来源）；松手时把 `--tpp-shift` 的同步推到下一帧；手指按着时定时扫描完全停掉
   （它会读几何 = 强制重排，正好卡在拖动的每一帧上）。
6. **面板精简**：常用只剩 4 个开关 + 默认名字下拉 + 2 个数值，其余全折进「高级设置」。

## v1.4.0：安卓 WebView 的「输入法盲区」+ 外观改动收回

真机诊断结果（TauriTavern v1.6.5，安卓）：

```
layoutH=800 base=800 vvH=800 ime=0 shrink=0
visible=0..800 inset=0 kbd=no
need=-48 shift=0
```

也就是**输入法弹出时页面一点都察觉不到**：布局视口没缩、`visualViewport` 没缩、原生层也没注入
`--tt-ime-bottom`。既然算出来「没有输入法」，自然一次都没顶过 —— 之前看到的上移是 WebView 自己干的。
这种环境（`adjustNothing` / 原生层不上报 inset）只能这样处理，v1.4.0 就是这么做的：

1. 输入框拿到焦点后先等 **350ms**，看有没有真实信号；
2. 等不到 → 断定这是「输入法盲区」，先试 **VirtualKeyboard API**（`navigator.virtualKeyboard`，
   能拿到真实键盘矩形就用真实值），拿不到就**按屏幕比例假定**一个高度（默认 45%，可调）；
3. 之后按这个高度正常避让：输入框 + 「取消 / 确认」一起顶到假定的键盘上方，上面的内容推出屏幕，
   手指还能拖回来看；
4. 盲区里**只能靠失焦判断输入法收起**（那个环境下按收起键既不失焦也没有任何信号），所以点空白处
   收键盘会回位，按输入法自带的收起键不会 —— 这种情况自己往下拖一下即可。真实信号一出现就以它为准。

另外按用户要求**把外观改动收回去了**：`widePopup` 默认关（弹窗宽度就是原生 500px，窄屏也不再收边距），
老设置里存着的 `true` 会被一次性迁移成 `false`。输入框高度 42px 和「名字保持一行」还留着（这两条是
你自己要的），不想要就在面板里各点一下关掉。

## v1.3.0 修了什么（真机上「改了跟没改一样」的三个原因）

1. **输入法高度被算两遍**：安卓 WebView 已经把布局视口压小（输入法那块已经不在视口里了），
   TauriTavern 的原生层又往页面注入 `--tt-ime-bottom`。两个信号叠加 → 算出来的可见区几乎是 0 →
   需要的避让量大到爆表 → 每次都被夹在「输入框顶部贴屏幕顶」这条红线上。**结果就是不管我怎么改
   目标，位移都一样**。现在只在别的信号都没反映出输入法时才用那个 CSS 变量。
2. **弹窗可能根本没被接管**：原来只有两条钩子（`HTMLDialogElement.prototype.showModal` 补丁 +
   body 直接子节点的 MutationObserver）。老 WebView 没有 `HTMLDialogElement`、客户端走 dialog
   polyfill、用 `show()` 而不是 `showModal()`、或者把弹窗塞进容器里，这两条都会漏。现在加了
   **整棵树的观察 + 每 250ms 扫一遍 `.popup`**，并且不再要求它必须是 `<dialog>`。
3. **输入框外观被静默跳过**：弹窗还没打开时量不到输入框（`offsetParent` 是 null），那一次的
   高度 / 单行处理就没做。现在开窗后会再补一次。

另外：手动拖动的上限从「自动避让算出来的量」放宽成红线本身（输入框顶部不出屏），想把上面的内容
推出去多少就推多少。

## 排查不动的时候

扩展面板里勾上 **「在弹窗里显示诊断信息（排查用）」**，再打开命名弹窗，弹窗底部会多出一小块：

```
tpp v1.5.0 hook=showModal pops=1 enh=1
layoutH=608 base=608 vvH=608 ime=0 shrink=0
visible=0..334 inset=274 kbd=YES src=assumed
blind=1/seen=1 assume=274 vk=on mobile=1 arm=1 settle=0
dlg=-271..319 input=91..133 ctrls=148..176
tag=DIALOG css=1 ctrlsInDlg=1/doc=1 in1line=1 inH=42
need=281 shift=-281 dragMin=-363 hardMin=-363 btn=YES
last: 557ms:-281(assumed) 296ms:0(kbd-closed) 1ms:-281(assumed)
```

怎么读：`src=` 是输入法高度的来源（`viewport` / `ime-var` / `vk-api` / `assumed` / `none`），
`blind=1` 表示这个环境测不出输入法、正在按比例假定，`seen=1` 表示这件事已经记住了（下次点输入框
立刻上顶，不用再等）；`arm=1` 表示插件认为「输入法要来了」，`settle=1` 表示刚回位、正在冷静期里；
`enh=1` 才说明这个弹窗被接管了；`css=1` 说明 style.css 加载了；`visible=..` 是我们认为
的可见区（`kbd=YES` 时它的下沿就是我们以为的输入法上沿）；`btn=YES` 说明「取消/确认」
在我们算的可见区里。如果 `btn=YES` 但你眼睛看到按钮还被键盘挡着，说明**输入法比我们
以为的高** —— 把「输入法占屏幕高度 (%)」调大（比如 55），或者高级设置里勾「一次顶到最高」。

**最后那行 `last:` 是位移流水**（最近 5 次，`多久以前ms:位移(原因)`）。弹窗自己跳一下、闪一下
这类问题事后截图是看不出来的，看这行就知道是谁在动它：`assumed`/`viewport` = 避让顶起，
`kbd-closed` = 输入法收了回位，`drag` = 手指拖的，`idle` = 没事回原位。

## 怎么确认装上的是哪一版

「扩展」面板里这个扩展的标题后面直接写着版本号（例如 **v1.5.0**）；控制台也会打
`[popup-polish] ready v1.5.0`。看到的还是旧版本号 = 客户端还在跑旧文件（更新完要重启客户端 /
重新加载页面，WebView 里已经 import 过的模块不会自己重新求值）。

## 安装

**方式 A（推荐，能一键更新）**：把这个文件夹的内容（`manifest.json` / `index.js` / `style.css`）
推到一个 GitHub 仓库的**根目录**，然后在酒馆里「扩展 → 安装扩展 → 填 Git URL」。

**方式 B（手动）**：把整个 `tavern-popup-polish` 文件夹放进
`data/<你的用户名>/extensions/`（SillyTavern）或 TauriTavern 对应的扩展目录，重启客户端。

## 设置

「扩展」面板里的 **弹窗顺手 + 密钥小眼睛**，每一条都能单独关：

常用（面板上面这几项）：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 启用本扩展 | 开 | 关掉后新开的弹窗完全是原生样子 |
| 密钥框右边加「小眼睛」 | 开 | 关掉会把密钥框还原成原生 `type=text` |
| 输入法弹出时把弹窗顶上去（带「取消 / 确认」） | 开 | |
| 可以用手指上下拖动弹窗 | 开 | |
| 记住上次没勾的项（新增配置弹窗） | 开 | 点保存时记住「哪几项没勾」，下次打开自动还原 |
| 切换连接配置时压住「后端错误 / Unauthorized」误报 | 开 | 只在「刚切完 + 还没连上 + 文案匹配」时压住那一条 toast，真连不上照常报 |
| 新配置的默认名字 | 只要模型名 | 另有「模型 - 预设」「API + 模型」「不改」 |
| 输入法占屏幕高度 (%) | 45 | **顶得不够（按钮还被挡）就调大，顶太多就调小** |
| 往上最多再拖 (px) | 150 | 自动避让之后还允许往上多拖多少；0 = 不许再往上 |

高级设置（折叠起来的，平时不用管）：不让密钥出现在提示文字里、输入类弹窗更宽、输入框更高、
名字保持一行、连按钮一起顶、一次顶到最高、测不出输入法高度时按比例假定、输入法没开也能拖、
弹窗比屏幕高时拖着看、输入法弹出时不让弹窗变形、换掉开窗动画、背景不做高斯模糊、

## 兼容 / 注意

- 只依赖 `dialog.popup` + `.popup-input` 这套结构（SillyTavern 1.12 起、TauriTavern 全系一致），
  不依赖任何内部函数，客户端升级一般不会失配。
- 输入法高度四路取信号，见上面的表；`scrollbar-width: none` 另有 `::-webkit-scrollbar` 兜底，
  老一点的 WebView 也不会把行高吃掉。
- 如果你还装着 **api-panel-layout** 并开着它的小眼睛，本扩展会自动跳过、不放第二只眼睛。
- 调试入口：控制台 `popupPolish`（`cfg()` / `viewport()` / `measure(dlg)` / `bounds(dlg)` / `popups`）。
  `measure(dlg).need > 0` 就是「底边被输入法压住了这么多 px」。
