# 弹窗顺手 + 密钥小眼睛 (tavern-popup-polish) v1.3.0

**为手机上的 SillyTavern（浏览器访问）和 TauriTavern（安卓 WebView）做的**，桌面上也能用。
只动两处：**API 密钥框**和**输入类弹窗**，别的地方一个字不改。

## 它做了什么

### 1. 密钥框右边的小眼睛
- 「自定义 API 密钥」输入框右边（原生小钥匙左边）多一颗眼睛，点一下看明文，再点一下遮回去。
- 原生的密钥框是 `type="text"`，装上后默认遮成圆点，所以平时截屏 / 递手机都不会漏。
- 客户端存完密钥就会清空输入框，所以框空着的时候点眼睛 = 向后端要**已存的那把密钥**（走
  `/api/secrets/find`，跟原生「查看隐藏的 API 密钥」是同一个开关；如果客户端没开
  Allow Keys Exposure 会提示你去开）。
- 我们填进去的明文在你点「连接 / 加载模型」等任何按钮之前会自动抹掉 —— 否则客户端看到框里
  有字，会把同一把密钥再存一遍。你**自己手打**的内容不会被动。
- 顺带挡掉客户端把已存密钥写进输入框提示文字（placeholder）的行为，那里显示的是明文且不受遮罩。

### 2. 输入类弹窗（新增 / 改名 API 连接配置、各种「起个名字」）
- **更宽更高**：原生固定 500px、输入框只有一行文字高（很扁）。现在宽度可调（默认 640，窄屏自动
  贴到 `100dvw - 12px`），输入框最小高度 42px。
- **名字永远一行**：原生是 `rows=1` 的 textarea，名字长了会折到第二行看不见。现在 `wrap=off` +
  `white-space: pre`，超长就继续往右延伸，光标走到哪就滚到哪（滚动条隐藏，不占高度）。
- **输入法避让（v1.2.0 改了目标）**：输入法一弹出，把整个弹窗往上顶，直到**输入框和「取消 /
  确认」那一排一起露在输入法上方**（离输入法上沿留 10px）。上面那十来个勾选项该顶出屏幕就顶出去
  —— 这样不用收输入法就能直接点保存。唯一的红线是「正在输入的那个框不能被推出屏幕顶部」。
- **手指拉回来看上面**：顶上去以后，在弹窗任意空白处（标题、说明文字、勾选框区域、弹窗外的暗
  背景）上下滑动就能把它拉回来看，**滑动过程不会收输入法**（我们把这一串触摸的默认行为拦了，
  连带取消了 click 和焦点变化）。往下最多回到原位，往上最多到上面那个极限，都拉不过头。
  在输入框里滑动是选字、在按钮上滑动是按按钮，都不会误拖窗口。
- **拖动跟手（v1.2.0）**：位移写成内联 `translate3d`，不写 CSS 自定义属性 —— 自定义属性会继承，
  改一次弹窗里每个子元素都要重算样式，每帧几十次就是「拖起来卡卡的」的真凶。再加上一帧只写一次
  （touchmove 比刷新率密得多）、拖动时关掉过渡和背景模糊、拖动中不再做任何测量。
- **点空白处照旧**：轻点（位移 < 8px）不算拖动，原生该收输入法就收。
- **输入法一收就回原位（v1.2.0 修）**：不管是点空白、**输入法自带的收起键**还是返回键，
  也不管这一轮里你有没有用手拖过，弹窗都会滑回原位。（安卓上后两种方式不会让输入框失焦，
  v1.1.0 靠失焦判断，所以按收起键时会卡在被顶起的位置。）
- **不卡了**：原生开窗动画是 `scaleY(0) → scaleY(1)`（整窗竖向拉伸 → 每帧文字重排重光栅化）+
  背景实时高斯模糊 + 输入法弹出让 `100dvh` 变小导致弹窗当场变形，三件事同帧发生，就是那股顿挫感。
  现在换成 150ms 的位移 + 淡入（纯合成器动画）、开窗时不做模糊、并把弹窗高度钉在输入法弹出前的
  视口高度上。还嫌顿可以再打开「等动画结束再弹输入法」。

## 手机上的三种输入法行为（都测过）

安卓上「输入法弹出」在不同环境里表现完全不同，插件四路取信号，哪一路都能兜住：

| 环境 | 输入法弹出时发生什么 | 插件靠什么发现 |
| --- | --- | --- |
| 手机浏览器（Termux 里的 SillyTavern、Chrome/Edge 等） | 只缩 `visualViewport`，布局视口不变 | `visualViewport.height / offsetTop` |
| TauriTavern（安卓 WebView） | 原生层往页面注入输入法高度 | CSS 变量 `--tt-ime-bottom` |
| WebView 的 adjustResize 模式 | **整个布局视口**被压小，inset 恒为 0 | 记住输入法弹出前的最大视口高度当基线（只在手机 UA 下启用） |
| 都读不到（很少见） | — | 250ms 轮询兜底；实在测不到就只是不自动推，其它功能照常 |

另外两条只对手机有意义的处理：

- **窄屏（≤600px）收边距**：手机上「变宽」的空间几乎全在边距里 —— 原生弹窗左右各留 2em(≈30px)
  空白 + 自己 14px padding + 内容区 8px，380px 的屏幕输入框只剩 ≈320px。窄屏下这三层收到
  10 / 8 / 4px，输入框实打实宽出 30~40px（≈两个汉字）。
- **弹窗比屏幕高时可以拖着看**：手机上「新增API连接配置」有十来个勾选项，弹窗常常比屏幕还高、
  顶部被切掉一截（输入法 adjustResize 时尤其明显）。这时不用输入法也能上下拖，往下最多拖到
  顶部刚好露出来，松手不会被拽回去；一旦输入法弹出，立刻改回「以名字可见为准」。
- **安卓返回键 / 输入法自带的收起键都不会让输入框失焦**，所以「输入法这一轮」是靠视口状态翻转判断的：
  一轮结束 → 一定回原位并解锁；再弹出 = 新一轮，重新自动避让。不靠 `focusout`（那样会漏）。
- **兜底一路**：万一某个环境的输入法高度四路都读不出来，只要「焦点在输入框里」且「弹窗底边确实
  被压在可见区外」，也会照样往上顶。没在打字时绝不动任何弹窗。

## v1.3.0 修了什么（真机上「改了跟没改一样」的三个原因）

1. **输入法高度被算两遍**：安卓 WebView 已经把布局视口压小（输入法那块已经不在视口里了），
   TauriTavern 的原生层又往页面注入 `--tt-ime-bottom`。两个信号叠加 → 算出来的可见区几乎是 0 →
   需要的避让量大到爆表 → 每次都被夹在「输入框顶部贴屏幕顶」这条红线上。**结果就是不管我怎么改
   目标，位移都一样**。现在只在别的信号都没反映出输入法时才用那个 CSS 变量。
2. **弹窗可能根本没被接管**：原来只有两条钩子（`HTMLDialogElement.prototype.showModal` 补丁 +
   body 直接子节点的 MutationObserver）。老 WebView 没有 `HTMLDialogElement`、客户端走 dialog
   polyfill、用 `show()` 而不是 `showModal()`、或者把弹窗塞进容器里，这两条都会漏。现在加了
   **整棵树的观察 + 每 250ms 扫一遍 `.popup`**，并且不再要求它必须是 `<dialog>`。
3. **输入框外观被静默跳过**：弹窗还没打开时量不到输入框（`offsetParent` 是 null），那一次的
   高度 / 单行处理就没做。现在开窗后会再补一次。

另外：手动拖动的上限从「自动避让算出来的量」放宽成红线本身（输入框顶部不出屏），想把上面的内容
推出去多少就推多少。

## 排查不动的时候

扩展面板里勾上 **「在弹窗里显示诊断信息（排查用）」**，再打开命名弹窗，弹窗底部会多出一小块：

```
tpp v1.3.0 hook=showModal pops=1 enh=1
layoutH=770 base=770 vvH=770 ime=0 shrink=0
visible=0..423 inset=347 kbd=YES
dlg=-209..407 input=221..263 ctrls=278..306
tag=DIALOG css=1 ctrlsInDlg=1/doc=1 in1line=1 inH=42
need=286 shift=-286 hardMin=-499 btnVisible=YES
```

怎么读：`enh=1` 才说明这个弹窗被接管了；`css=1` 说明 style.css 加载了；`visible=..` 是我们认为
的可见区（`kbd=YES` 时它的下沿就是我们以为的输入法上沿）；`btnVisible=YES` 说明「取消/确认」
在我们算的可见区里。如果 `btnVisible=YES` 但你眼睛看到按钮还被键盘挡着，说明**输入法比我们
以为的高** —— 把「弹窗底边与输入法的间距」调大（比如 60），或者直接勾「一次顶到最高」。

## 怎么确认装上的是哪一版

「扩展」面板里这个扩展的标题后面直接写着版本号（例如 **v1.2.1**）；控制台也会打
`[popup-polish] ready v1.2.1`。看到的还是旧版本号 = 客户端还在跑旧文件（更新完要重启客户端 /
重新加载页面，WebView 里已经 import 过的模块不会自己重新求值）。

## 安装

**方式 A（推荐，能一键更新）**：把这个文件夹的内容（`manifest.json` / `index.js` / `style.css`）
推到一个 GitHub 仓库的**根目录**，然后在酒馆里「扩展 → 安装扩展 → 填 Git URL」。

**方式 B（手动）**：把整个 `tavern-popup-polish` 文件夹放进
`data/<你的用户名>/extensions/`（SillyTavern）或 TauriTavern 对应的扩展目录，重启客户端。

## 设置

「扩展」面板里的 **弹窗顺手 + 密钥小眼睛**，每一条都能单独关：

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| 启用本扩展 | 开 | 关掉后新开的弹窗完全是原生样子 |
| 密钥框右边加「小眼睛」 | 开 | 关掉会把密钥框还原成原生 `type=text` |
| 不让已存的密钥出现在提示文字里 | 开 | placeholder 换成「密钥已保存」 |
| 输入类弹窗更宽 | 开 | 宽度见下面的数值项 |
| 输入框更高（不那么扁） | 开 | 高度见下面的数值项 |
| 名字超长保持一行往右延伸 | 开 | |
| 输入法遮住时把弹窗往上推 | 开 | |
| 连「取消 / 确认」一起顶到输入法上方 | 开 | 关掉则只保证输入框可见，按钮可能还被挡着 |
| 一次顶到最高 | 关 | 不管输入法多高，直接顶到红线（输入框贴屏幕顶）。输入法高度测不准时最稳 |
| 可以用手指上下拖动弹窗 | 开 | |
| 输入法没开时也能拖 | 关 | 平时防误触，只在输入法弹出（或已被推上去）时才能拖 |
| 弹窗比屏幕高时可以拖着看 | 开 | 手机上弹窗顶部常被切掉，拖着看被切掉的部分 |
| 输入法弹出时不让弹窗变形 | 开 | 把 `max-height` 钉住，防 `dvh` 抖动 |
| 换掉原生开窗动画 | 开 | |
| 弹窗背景不做高斯模糊 | 开 | 手机上省一大笔合成开销，只保留压暗 |
| 等动画结束再弹输入法 | 关 | 最顺，但个别 WebView 可能不自动弹输入法，觉得需要再开 |
| 在弹窗里显示诊断信息 | 关 | 排查用，见上面「排查不动的时候」 |
| 调试日志 | 关 | |

数值项：弹窗目标宽度 640px、输入框最小高度 42px、弹窗底边与输入法的间距 16px、开窗动画时长 150ms。
弹窗相关的改动在**下一次打开弹窗**时生效。

## 兼容 / 注意

- 只依赖 `dialog.popup` + `.popup-input` 这套结构（SillyTavern 1.12 起、TauriTavern 全系一致），
  不依赖任何内部函数，客户端升级一般不会失配。
- 输入法高度四路取信号，见上面的表；`scrollbar-width: none` 另有 `::-webkit-scrollbar` 兜底，
  老一点的 WebView 也不会把行高吃掉。
- 如果你还装着 **api-panel-layout** 并开着它的小眼睛，本扩展会自动跳过、不放第二只眼睛。
- 调试入口：控制台 `popupPolish`（`cfg()` / `viewport()` / `measure(dlg)` / `bounds(dlg)` / `popups`）。
  `measure(dlg).need > 0` 就是「底边被输入法压住了这么多 px」。
